# SAQ QURYLYS

Веб-прототип для мониторинга рисков в долевом жилищном строительстве Казахстана. Помогает аналитику связывать рекламные публикации с ЖК, получать AI-гипотезы с цитатами, вручную проверять факторы R1–R6, рассчитывать объяснимый балл риска и формировать печатную сигнальную карточку.

> Данные seed-набора вымышлены и явно помечены как демонстрационные. Приложение не устанавливает факт правонарушения и не отправляет материалы в государственные органы.

## Функции

- Обзор, реестр ЖК, поиск и фильтр по зоне риска.
- 8 демонстрационных ЖК и 12 демонстрационных публикаций.
- Добавление публикации вручную и связывание с ЖК.
- Серверный AI-анализ через OpenAI-compatible API (DeepSeek по умолчанию); цитаты проверяются как точные подстроки исходного текста.
- Факторы R1–R6 со статусами «Ожидает проверки», «Подтверждён», «Отклонён». Для отклонения требуется причина.
- Серверный детерминированный скоринг и история действий.
- Подтверждение сигнала / возврат на дополнительную проверку.
- Печатная сигнальная карточка: в браузере можно выбрать «Сохранить как PDF».
- JSON-хранилище в `data/store.json`, создаётся автоматически и сохраняется между перезапусками.

## Требования

- Node.js 20 или новее.
- Для AI-анализа необходим API-ключ выбранного провайдера. Остальные функции работают без ключа.

## Запуск

```bash
cp .env.example .env
# Windows PowerShell: Copy-Item .env.example .env
npm start
```

Откройте http://localhost:8787. Сервер одновременно отдаёт API и статический интерфейс. При первом запуске создаётся `data/store.json` с демо-данными.

### Настройка AI

В `.env` укажите:

```env
AI_PROVIDER=deepseek
AI_API_KEY=ваш_ключ
AI_BASE_URL=https://api.deepseek.com/v1
AI_MODEL=deepseek-chat
PORT=8787
```

Для OpenAI используйте `AI_PROVIDER=openai`, `AI_BASE_URL=https://api.openai.com/v1`, `AI_MODEL=gpt-4o-mini`. Не публикуйте `.env`. Если ключ не задан, интерфейс честно покажет ошибку настройки и не подменит её фальшивым успешным анализом.

Node.js сам по себе не загружает `.env` во всех версиях, поэтому для запуска с переменными из файла используйте Node.js 20.6+ с `node --env-file=.env server/index.mjs` либо задайте переменные в оболочке. Удобная команда через npm:

```bash
node --env-file=.env server/index.mjs
```

## Модель риска

- R1: +35
- R2: +25
- R3: +10
- R4: +15
- R5: +10
- R6: +5

Учитываются только подтверждённые факторы; итог ограничен 100. Зелёная зона: 0–24. Жёлтая: 25–59. Красная: 60+ только при одновременном подтверждении R1 и R2. Если балл 60+ без обоих факторов, зона остаётся жёлтой.

## API

- `GET /api/health`
- `GET /api/state`
- `POST /api/posts`
- `POST /api/posts/:id/analyze`
- `POST /api/signals`
- `PATCH /api/signals/:id/factors/:R1-R6`
- `POST /api/signals/:id/confirm`
- `POST /api/signals/:id/return`
- `GET /api/signals/:id/export`
- `POST /api/reset-demo` — перезаписывает хранилище исходным демо-набором.

## Демонстрация на хакатоне

1. Откройте обзор и покажите реестр из 8 демонстрационных ЖК.
2. Перейдите в публикации и откройте материал с предложением депозита.
3. Запустите AI-анализ с настроенным API-ключом; покажите точные цитаты и гипотезы.
4. Создайте сигнал, подтвердите или отклоните факторы и объясните пересчёт балла.
5. Покажите историю изменений и распечатайте сигнальную карточку в PDF.
6. Покажите контрастные seed-сценарии A, B и C.

## Ограничения MVP

- Нет автоматического сбора данных из социальных сетей и закрытых государственных API.
- Нет пользовательской авторизации и ролевой модели.
- Хранилище JSON рассчитано на демонстрационный MVP, а не конкурентную многопользовательскую нагрузку.
- Географические координаты не предоставлены; карта заменена схемой с явной маркировкой.
- AI-анализ требует внешнего ключа и сетевого доступа; тестовые данные не маскируются под реальный AI-ответ.


## Авторизация и управление сессиями

1. Скопируйте `.env.example` в `.env` и задайте уникальный `ADMIN_PASSWORD` (не используйте пароль из примера).
2. Запустите `npm start`; при первом запуске создаётся начальный администратор из `ADMIN_LOGIN` и `ADMIN_PASSWORD`, если администраторов ещё нет.
3. Новые пользователи регистрируются через форму и получают статус ожидания. Одобрение и управление сессиями доступны администратору во вкладке «Сессии».
4. Сессия действует 12 часов, cookie имеет флаги HttpOnly и SameSite=Lax. Для публичного HTTPS-развёртывания установите `NODE_ENV=production`, чтобы включить Secure cookie.

Учётные записи, сессии и аудит хранятся в JSON-хранилище приложения. Для многопроцессного/публичного развёртывания с несколькими экземплярами сервера потребуется транзакционная БД и управление миграциями.
